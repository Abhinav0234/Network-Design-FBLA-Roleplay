📐 Competency 1

Planning, Cabling & Architectures

Understanding the lifecycle of a network from requirements to physical wiring.

📋 The Network Design Process

A structured approach to ensure the network meets business objectives:

  • 1. Analyze Requirements: Gather functional (e.g., VoIP support), performance (e.g., high bandwidth), and security needs. Use traffic analysis surveys.
  • 2. Planning: Finalize budget and perform risk assessments before major changes.
  • 3. Logical Design: Architect IP addressing, switching, and routing protocols. Create a logical network diagram.
  • 4. Physical Design: Select hardware, plan device placement (e.g., APs for wireless coverage), and define the physical topology schema.
  • 5. Test & Document: Use simulation software. Create a network design proposal.
  • 6. Implementation & Handoff: Install hardware. Client signs an acceptance document based on network documentation.
  • 7. Continuous Improvement: Schedule periodic design reviews.

🔌 Physical Implementation & Cabling

  • Twisted Pair (Copper): Uses RJ-45. Cat5e (1 Gbps), Cat6 (10 Gbps, shorter distances, higher frequencies), Cat6a (10 Gbps). Susceptible to EMI unless shielded (STP).
  • Coaxial: Broadband internet. Uses F-type or BNC connectors.
  • Fiber Optic: Uses light. Immune to EMI. Consists of core, cladding (keeps light inside), buffer, and jacket. Single-mode (long distance, laser) vs Multi-mode (short distance, LED). Connectors: LC, SC, ST.
  • Wired vs Wireless: Transmission speed is a primary consideration when choosing between wired and wireless connections.

🏢 Wiring Systems

Horizontal Wiring: Runs from telecom closet to wall plates in offices.
Vertical (Backbone): Runs between floors to connect closets.

🏢 Client-Server (Domain Controlled)

Dedicated servers provide resources to clients. Essential for enterprise environments. Offers centralized security, centralized backups, and high scalability.

🤝 Peer-to-Peer (P2P)

All computers hold equal status. Best for small environments (under 10 users). Cheap and easy to set up, but lacks centralized management and security.

Legacy P2P (Gnutella): An older decentralized protocol for shared resource searching.

📐 Scalability Principle

Regardless of topology, a core design principle is scalability — ensuring a network can easily expand as new employees join without major redesigns.

🌐 Web Server

Hosts web pages using HTTP/HTTPS. Common software: IIS, Apache, Nginx.

The OSI Model

The foundation of all networking. Memorize this — every layer matters.

6PresentationData formatting, encryption, compression. SSL/TLS operates here.
5SessionManages sessions & connections. Authentication, reconnection handling.
4TransportEnd-to-end delivery. TCP (reliable) vs UDP (fast). Port numbers live here. PDU: Segment.

🕸️ Architectures

Network Topologies

Understand the layout options and when to recommend each.

⭐

Star Topology

All devices connect to a central switch/hub. Easy to manage, scalable. Single point of failure at center. Most common in LANs.

🔷

Mesh Topology

Every device connects to every other. Maximum redundancy and reliability. Expensive and complex. Ideal for critical infrastructure.

🔵

Ring Topology

Devices form a circular chain. Data travels in one direction. Simple but a single break disrupts the network. Token Ring used this.

📏

Bus Topology

All devices share a single cable (backbone). Simple and cheap. Collisions increase with more devices. Legacy — rarely used today.

🌲

Tree (Hybrid) Topology

Hierarchical combination of star topologies. Scalable for large organizations. Used in campus networks. Good for growing businesses.

🔀

Hybrid Topology

Combines two or more topologies. Flexible and scalable. Can be complex to design and manage. Most enterprise networks are hybrid.

🔧 Hardware

Network Devices & Server Roles

Know each device, its OSI layer, and when to use it.

🔀 Router

Layer 3 (Network) — Routes packets between different networks using IP addresses. Essential for connecting LANs to WANs and the internet. Supports NAT, DHCP, and ACLs. Connects multiple switches in different wings of a building.

🔄 Switch

Layer 2 (Data Link) — Forwards frames using MAC addresses within a LAN. Supports VLANs, STP, and port security. Much smarter than a hub.

🛡️ Firewall

Layer 3-7 — Filters traffic based on rules. Can be hardware or software. Stateful firewalls track connections. Next-gen firewalls inspect application data.

📡 Access Point (AP)

Layer 1-2 — Extends wired network wirelessly. Supports 802.11 standards (a/b/g/n/ac/ax). Enterprise APs support WPA3, RADIUS auth, and band steering.

⚖️ Load Balancer

Layer 4-7 — Distributes traffic across multiple servers to ensure availability. Prevents overload. Methods: round-robin, least connections, IP hash.

🔌 Hub

Layer 1 (Physical) — Simple repeater that broadcasts all data to all ports. No intelligence. Causes collisions. Obsolete — replaced by switches.

🌉 Gateway

Layer varies — Translates between different network protocols or architectures. Often used as the default gateway (router) connecting a LAN to the internet.

💳 Network Interface Card (NIC)

Layer 1/2 — Physical hardware connecting a workstation to the network. Every NIC has a unique, hardcoded MAC address burned in by the manufacturer.

📊 Network Monitor / SNMP

Management — SNMP (Simple Network Management Protocol) monitors device health, bandwidth, and alerts. Tools: Nagios, SolarWinds, PRTG.

🖥️ Server Types

Server Roles & Application Servers

🔐 Domain / Directory Server

Manages network security and authentication (e.g., Active Directory using LDAP/Kerberos).

📂 File / Print Server

Provides centralized storage and print job spooling for the organization.

⚙️ Application Server

Hosts business logic and backend applications for client devices.

📧 Communication / Mail Server

Handles messaging (Exchange, Postfix). Uses SMTP (sending), IMAP/POP3 (receiving).

🌐 Web Server

Hosts web pages using HTTP/HTTPS. Software: IIS, Apache, Nginx.

🌐 Addressing

IP Addressing, VLANs & Segmentation

Understand addressing schemes, network segmentation, and logical organization.

🅰️ Class A

10.0.0.0 — 10.255.255.255

Large enterprises. 16 million+ hosts.

🅱️ Class B

172.16.0.0 — 172.31.255.255

Medium-sized organizations.

🅲 Class C

192.168.0.0 — 192.168.255.255

Small networks. Home & small office.

📌 RFC 1918 — These are non-routable private addresses used strictly for internal networks.

🔀 VLANs (Virtual LANs)

  • Logically group devices on the same broadcast domain regardless of physical switch location.
  • Used for security, segmentation, and reducing broadcast traffic.
  • Logical Segmentation: Separate departments (e.g., Accounting and HR) on different VLANs.
  • 802.1Q: The standard protocol for VLAN tagging on network trunks.

✂️ Network Segmenting

  • Segmenting: Breaking a large network into smaller subnets to reduce broadcast traffic and increase speed.
  • Routers and Layer 3 switches are used to route between segments.
  • Subnetting: Using subnet masks (e.g., 255.255.255.0) to define network boundaries.
  • Improves performance, security, and manageability.
🔐 Defense

Network Security

20% of the test. Critical for roleplay scenarios too.

Firewalls filter traffic based on rules (ACLs). Types include:

  • Packet-filtering: Inspects headers only (IP, port). Fast but basic.
  • Stateful: Tracks connection state. Knows if traffic is part of an established session.
  • Next-Gen (NGFW): Deep packet inspection, application awareness, IDS/IPS built-in.
  • Software vs Hardware: Windows Firewall (software) vs Cisco ASA (hardware appliance).

Firewall Policies:

  • Permissive: Permits all ports except those explicitly denied.
  • Restrictive: Denies all ports except those explicitly allowed (best practice).

VPNs create encrypted tunnels for secure remote access:

  • IPSec: Suite of protocols for encrypting IP traffic. Commonly used for site-to-site VPNs.
  • SSL/TLS VPN: Works through web browsers. Used for remote employee access.
  • PPTP / L2TP: Older VPN tunneling protocols used over public networks.
  • WPA3: Latest Wi-Fi security standard. Uses SAE (Simultaneous Authentication of Equals).
  • BitLocker: Windows full-disk encryption. Protects data at rest.

A continuous lifecycle model for security policy compliance. Phases:

  • Secure: Implement policies, firewalls, and patching.
  • Monitor: Watch for anomalous traffic and logs.
  • Test: Perform vulnerability scans and penetration testing.
  • Improve: Review results and refine the security posture.

Regular patching of network operating systems helps protect against newly discovered vulnerabilities.

  • DoS/DDoS: Overwhelms resources with traffic. Mitigate with rate limiting, CDNs, and anti-DDoS services.
  • Phishing: Social engineering via fake emails. Counter with user training and email filtering.
  • Malware: Viruses, worms, ransomware. Use endpoint protection, updates, and network segmentation.
  • Man-in-the-Middle: Intercepts communication. Prevent with encryption (HTTPS, VPN).
  • DMZ (Demilitarized Zone): Subnetwork exposing external-facing services (Web, FTP, Mail) to the internet, keeping internal LAN secure behind a second firewall.
  • Intranet: A private network accessible only to employees.
  • Extranet: Securely shares part of a business's operations with external suppliers/partners.
  • MAC (Mandatory Access Control): Strictest model. OS restricts access based on security clearances and labels.
  • DAC (Discretionary Access Control): Data owner defines who gets access. Standard in Windows.
  • Remote Management: Use SSH (port 22) instead of unencrypted Telnet (port 23).
  • Dark Fiber: Fiber optic cable that has been laid underground but is not currently in use or "lit."

"Never trust, always verify." Core principles:

  • Verify every user, device, and connection — even inside the network.
  • Least privilege access — users get only what they need.
  • Micro-segmentation — isolate resources to limit breach impact.
  • Continuous monitoring and validation of trust level.
  • Multi-factor authentication (MFA) is a key component.
  • Disaster Recovery vs Business Continuity: DR is technical steps to restore IT. BC is the broader plan to keep the business operational.
  • 3-2-1 Rule: 3 copies, 2 different media, 1 offsite (cloud).
  • RTO (Recovery Time Objective): Max acceptable downtime.
  • RPO (Recovery Point Objective): Max acceptable data loss (time).
  • Cloud Backup: AWS, Azure, Google Cloud. Automated, scalable, geo-redundant.
  • Hot/Warm/Cold Sites: Failover locations with varying readiness levels.
🛠️ Competency 2

Troubleshooting & Diagnostics

A systematic approach to identifying and fixing network faults.

1

Identify the Problem

Gather information, question users, and attempt to duplicate the issue.

2

Establish a Theory

Start with the obvious (e.g., check physical connections, power) and establish a theory of probable cause.

3

Test the Theory

Test your theory to determine the exact cause of the problem.

4

Plan of Action

Establish a plan of action to resolve the problem and implement the solution safely.

5

Verify Functionality

Verify full system functionality and implement preventive measures.

6

Document

Document your findings, actions taken, and final outcomes for future reference.

💻 Command Line Utilities

  • ping: Tests connectivity using ICMP echo requests.
  • tracert / traceroute: Maps the routing path a packet takes.
  • ipconfig / ifconfig: Displays TCP/IP config values.
  • ipconfig /displaydns: Shows locally cached DNS entries.
  • nslookup: Queries DNS to resolve hostnames to IPs.
  • netstat: Displays active network connections/ports.
  • ROMMON: Low-level OS for password recovery on Cisco routers.

🔧 Hardware Tools

  • Cable Tester: Verifies that a network cable is wired correctly and functioning physically.
  • Protocol Analyzer: Used to analyze packet loss, latency, and deep inspect traffic.
  • Loopback Plug: Tests Network Interface Cards (NICs) to ensure they can send and receive properly.

APIPA Address

If a device shows an IP of 169.254.x.x, it means it cannot reach the DHCP server to get a valid lease.

DNS Failure

If you can ping a site by IP but not by its domain name, the DNS server is down or misconfigured.

Permissions Issue

If a user can log into the network but cannot open a specific file, it's likely an ACL or sharing permission issue.

⚙️ Competency 3

Administration, Optimization & Backup

Keeping the network optimized, documented, and resilient against failures.

  • Naming Conventions: Standardizing computer, user, and group names is critical for scale.
  • FQDN (Fully Qualified Domain Name): The complete domain name (e.g., server1.example.com).
  • Asset Management: Tracking physical hardware you own and its location.
  • Configuration Management: Recording OS versions and specific configs on switches/routers.
  • Change Management: Documenting upgrades and changes for compliance.
  • File Organization: Apply principle of least privilege. Manage disk quotas, NTFS/Share permissions, and use file compression to save space.
  • QoS (Quality of Service): Prioritizes critical traffic (like VoIP) over less critical data.
  • Load Balancing: Distributes traffic across multiple servers to prevent single points of failure.
  • Baselining & Monitoring: Establishing normal activity baselines to identify anomalies (e.g., alert when CPU hits 85%). Review logs regularly.
  • Capacity Planning: Using historical bandwidth data to decide when to upgrade internet service.

Maintenance Types:

  • Preventive: Upgrading firmware on switches to improve performance.
  • Corrective: Replacing a failed switch during off-peak hours to minimize disruption.
  • Predictive: Identifying potential issues before they cause failures.
  • Load Testing: Testing post-implementation to ensure the network can handle expected live traffic loads.
  • Coverage Testing: Testing a new wireless network by having users connect from various physical locations to map signal strength.

The Archive Bit is a file attribute that tells backup software if a file has changed.

  • Full Backup: Backs up everything, resets archive bit. Slowest to run, fastest to restore.
  • Incremental: Backs up data changed since last backup, resets archive bit. Fastest to run, slowest restore.
  • Differential: Backs up data changed since last full backup, DOES NOT reset archive bit.
  • Fault Tolerance: Ensures the network remains operational even if one main link fails.
  • Redundancy Testing: Intentionally disconnecting primary lines to verify failover to backup systems.
  • UPS (Uninterruptible Power Supply): Provides emergency battery backup power with surge suppression.
  • NAS (Network Attached Storage): Single storage device operating on data files over standard Ethernet.
  • SAN (Storage Area Network): Specialized, high-speed network providing centralized, fault-tolerant block-level storage.

RAID Levels:

  • RAID 0: Striping — speed, no redundancy.
  • RAID 1: Mirroring — high redundancy, 50% capacity.
  • RAID 3: Byte-level striping with a dedicated parity disk.
  • RAID 5: Striping with distributed parity (requires 3+ disks, tolerates 1 drive failure).

🎭 Competition Strategy

Roleplay Tips & Strategy

How to ace the 7-minute interactive presentation.

  • 1

    Read the Case Study Twice

    First pass: understand the scenario. Second pass: identify specific requirements, constraints, and budget considerations.

  • 2

    Structure Your Response

    Use a framework: Problem → Analysis → Solution → Implementation → Benefits. This keeps your presentation organized and logical.

  • 3

    Justify Every Decision

    Don't just say "use a star topology." Explain WHY: scalability, easier troubleshooting, fits the business size. Judges want reasoning.

  • 4

    Address Security First

    Always include firewalls, VPN for remote access, WPA3 for wireless, and a backup/disaster recovery plan. Judges love comprehensive security.

  • 5

    Use Technical Vocabulary

    Say "implement VLAN segmentation for department isolation" not "separate the networks." Specificity shows expertise.

  • 6

    Plan for Scalability

    Mention how your design can grow: modular switches, cloud integration, additional subnets. Businesses grow — your network should too.

  • 7

    Prepare for Judge Questions

    Common questions: "What if the main switch fails?" "How do you handle 50% growth?" "What's your budget breakdown?" Have answers ready.

  • 8

    Dress Professionally

    Professional business attire is required and scored (5 points). Suit/blazer, dress shirt, conservative colors. First impressions matter.

  • 9

    Use Your Notecards Wisely

    You get 2 notecards per person. Write key diagrams, IP schemes, or decision frameworks — not scripts. Speak naturally.

  • 10

    Maintain Eye Contact & Confidence

    Communication skills = 10 points. Speak clearly, make eye contact with judges, and show enthusiasm for your solution.
